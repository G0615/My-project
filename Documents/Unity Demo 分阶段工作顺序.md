# Unity Demo 分阶段工作顺序

更新：2026-09-19。本文件首次制定时仅做任务拆解；当前进度见第 7 节。每次执行仍遵守一个小任务的边界。

本文件控制后续开发顺序和每次任务的大小。玩法规则见[策划案](./Unity%20Demo%20策划案.md)，模块接口见[开发计划与模块架构](./Unity%20Demo%20开发计划与模块架构.md)。此前文档中的三线并行安排，改为下述逐项推进方式。

## 1. 后续如何推进

1. **每次默认只安排一个任务编号，例如 A01。** 使用一名 Luna xhigh 子 agent，不同时启动其他开发或审查 agent。
2. 主 agent 只交付该任务需要的规则、接口、文件范围和验收条件；不让子 agent 通读整段历史、顺手实现后续功能。
3. 每个任务只处理一个可独立检查的变化。建议控制在约 15～30 分钟的人工工作量；这只是拆分尺度，不是模型运行时间或 usage 承诺。仍然过大时，先拆成子编号。
4. 子 agent 完成指定变化和必要检查后停止。主 agent 做一次针对性验收，报告结果和下一个建议编号，**不自动派发下一项**。
5. 验收失败时，只修该任务的问题；跨模块问题另列编号，不在本轮扩展。用户明确授权一个小批次时，仍按编号串行，到指定边界停止。
6. 每个阶段结束都留下可体验或可检查的成果，用户可以在这里暂停。未明确安排的任务保持待办。
7. 用户已授权每次阶段性开发完成后提交并推送到本仓库 GitHub。提交前检查范围并记录验收结果；不提交本机缓存、临时编译产物或凭据，不自动开始下一阶段。

本次另获授权先提交一次已有内容作为草稿快照，用于验证 GitHub 提交与推送通路；该快照不代表功能验收通过。

模块是责任划分，不要求每个任务都建新类、另起框架或重写文件。现有草稿优先复用：已满足某项时，检查通过即可，不为了“完成任务”再写一遍。

## 3. 阶段顺序与完成目标

| 顺序 | 阶段 | 阶段结束时应得到什么 |
|---|---|---|
| P | 接手与边界确认 | 清楚哪些可复用、哪些待修；最小接口和验证环境明确 |
| A | 最小可操作场景 | 三角色可切换、移动，镜头跟随，F 只命中一个测试点 |
| B | 单次行为与反馈 | 领取、购买、捐献都能操作，并有正确的日志和飘字 |
| C | 共享加工 | 切果和打发可单人完成、多人加速，切人和离开不中断 |
| D | 蛋糕表达 | 三处贴果切、三处抹奶油，六个位置可辨认、可操作 |
| E | 偷吃与限时效果 | 筷子自动决定偷吃/捐献，减速与到期正确 |
| F | 庆典与奖杯 | 任意角色 F 举办，结算称号，三人领奖并各自回家放置 |
| G | 完整回顾 | 对本人奖杯 F 查看完整行为列表，可关闭、重开 |
| H | 整体体验与交付 | 全流程验收、必要修复、可运行构建与操作说明 |

主顺序为 **P → A → B → C → D → E → F → G → H**。不是把整张表一次发给 agent；表格只是待办队列。各阶段内按编号执行，特别依赖另注。每个任务的结束条件只覆盖其自身，阶段目标在最后一项统一检查。

## 4. 逐项工作清单

### P：接手与边界确认

| 编号 | 这次只做什么 | 结束条件 |
|---|---|---|
| P01 | 只读盘点现有草稿，对照本表标记“可复用 / 待验证 / 缺失” | 输出简短状态表，不改代码、不修错误 |
| P02 | 核对 ActorId、TargetId、事件、时间与返回结果的最小接口 | 列出接口冲突及其归属；不扩充通用框架 |
| P03 | 确认 Unity 许可证与当前代码的编译状态 | 记录真实结果；若受阻则保留明确阻碍，不启动后续开发 |

P 阶段结束后停下。若环境仍阻塞，只能由用户明确指定可独立检查的规则任务，不自动跳过场景阶段大范围写代码。

### A：最小可操作场景

| 编号 | 这次只做什么 | 结束条件 |
|---|---|---|
| A01 | 生成或修正地面、光照、相机和一名占位角色的场景入口 | 能进入场景；角色不坠落；旧场景保留 |
| A02 | 单角色移动与边界 | WASD / 方向键移动，斜向不额外加速，不能走出地面 |
| A03 | 增加另外两名角色与稳定编号/配色 | 三个实体同时存在，编号与红黄蓝对应 |
| A04 | 唯一输入与 1/2/3 切换 | 仅主控响应移动，切换不关闭其他角色对象 |
| A05 | 固定角度、固定视野的平滑跟随镜头 | 切人/走动只平移，快速切人仍跟随最新角色 |
| A06 | 一个测试目标的距离选择、高亮和 F 入口 | 角色靠近后可操作；一次按键只触发一次 |
| A07 | 两个相邻测试目标的选择与最小中文提示 | 同时只选一个，边界不闪烁；提示与实际动作一致 |
| A08 | 本阶段场景接线检查 | 重新打开场景后仍能移动、切人和交互；没有旧输入组件同时响应 |

此处只验证基础操作，不要求把所有正式交互点都接好。已有生成器含完整点位时可保留，验收仍只关注本阶段范围。

### B：单次行为与反馈

| 编号 | 这次只做什么 | 结束条件 |
|---|---|---|
| B01 | 一次动作生成一条有角色、目标、序号的事件 | 事件先记入完整历史，再通知显示；不建立库存余额 |
| B02 | 最近日志列表与角色配色 | 每条行为归属明确，重复刷新不重复记账 |
| B03 | 角色与目标两处短暂飘字 | 显示各自增减，连续操作可读，不出现内部对象 ID |
| B04 | 家园 F 领取水果 | 日志与角色飘字显示水果 +1，不检查库存 |
| B05 | 商店 F 购买鸡蛋 | 显示金币 -1、鸡蛋 +1，不检查余额 |
| B06 | 水果堆 F 捐献 | 角色水果 -1、广场水果 +1；不用先领取 |
| B07 | 鸡蛋堆 F 捐献 | 角色鸡蛋 -1、广场鸡蛋 +1；动作不串到水果堆 |
| B08 | 领取/购买/捐献的现场检查 | 三人轮流操作，日志与双端飘字归属正确，无虚构库存总量 |

筷子限制到 E 阶段接入，此时不提前实现偷吃。完整历史从 B01 起保留，回顾 UI 留到 G 阶段。

### C：共享加工

| 编号 | 这次只做什么 | 结束条件 |
|---|---|---|
| C01 | 单个工位的开始、推进、完成状态 | 单人约 10 秒；不自动续批 |
| C02 | 同批次的参与者去重 | 重复 F 不增人数、不重置进度；不影响后续新批次 |
| C03 | 后加入者的协作加速 | 两人从头约 5 秒；单人先做 4 秒、第二人加入后再约 3 秒 |
| C04 | 加工计时与主控/角色位置分离 | 切人、走开不中断；同一人可以参与两种工位 |
| C05 | 切果完成结果与个人归属 | 每批仅一次水果 -1、果切 +1；每位参与者都能关联本次完成 |
| C06 | 工位上方共享进度与简化工具动作 | 读条跟随工位显示，人数变化可见，完成停止动作 |
| C07 | 用同一套工位规则接入打发 | 一次鸡蛋 -1、奶油 +1；两个工位进度互不影响 |
| C08 | 共享加工针对性验收 | 单人/三人/迟到加入/重复加入/切人均符合规则，无重复公共产出 |

C01～C05 先验证切果；C07 才复用到打发。避免先复制两套计时器再修两遍。

### D：蛋糕表达

| 编号 | 这次只做什么 | 结束条件 |
|---|---|---|
| D01 | 蛋糕六等分的交互位置 | 3 果切点与 3 奶油区交替，均可接近且不抢目标 |
| D02 | 单个果切挂点状态与占位外观 | F 直接贴果切，重复 F 更新外观；无需加工前置 |
| D03 | 单个奶油区域状态与占位外观 | F 换色，只影响对应区域 |
| D04 | 扩展到全部 3+3 并验证反馈 | 六处独立可操作，增减、作者和视觉位置正确 |

### E：偷吃与限时效果

| 编号 | 这次只做什么 | 结束条件 |
|---|---|---|
| E01 | 筷子购买、有效期、重复购买刷新 | 默认 60 秒；金币 -10、筷子 +1；每人独立计时 |
| E02 | 水果/鸡蛋堆按筷子状态决定唯一动作 | 有筷只偷吃，无筷可捐献；没有模式切换键；到期提示立即恢复 |
| E03 | 四种物品的偷吃结果 | 各对应物品 -1；只更新该角色行为与效果，不读取库存 |
| E04 | 减速叠加、下限及统一十秒期限 | 基础 10、最低 0；再次偷吃刷新全部层数期限；到期一起清除 |
| E05 | 工具/减速 UI 与交互兼容检查 | 切走仍计时；筷子不影响加工、蛋糕、庆典；到下限不误报继续 -1 |

E04 的检查须包含“隔 6 秒再吃一次”和“连续吃 11 次”，不能只检查同一时间吃两次。

### F：庆典与奖杯

| 编号 | 这次只做什么 | 结束条件 |
|---|---|---|
| F01 | 四类参与资格的记录 | 开始/加入加工、装饰、偷吃、捐献分别达标；不比较次数 |
| F02 | 广场 F 庆典入口与一次性结算 | 任意角色可触发；称号保存为本轮快照；再次 F 不重算 |
| F03 | 三名玩家各颁发一座奖杯 | 无称号者也有；各自飘字与同色日志均为奖杯 +1；不重复发 |
| F04 | 庆典结果展示与关闭 | 显示三人称号/奖杯；可关闭；后台加工继续 |
| F05 | 三个属于各自角色的家园展示位 | 与苹果点分离；不能用别人的底座放自己的奖杯 |
| F06 | 奖杯放置与模型出现 | 已获奖杯者 F 放置；仅一座；此次输入不会继续打开回顾 |

F01 汇总 B～E 已发生的实际行为，不从中文日志反推资格。F02～F03 状态与 UI 分开，避免显示失败导致漏发或重发奖杯。

### G：完整个人回顾

| 编号 | 这次只做什么 | 结束条件 |
|---|---|---|
| G01 | 完整历史按活动和角色查询 | 包含本人协作记录，排除他人独立行为；按序、不重复 |
| G02 | 已放置奖杯的 F 查看入口 | 只读本人奖杯归属，不重新颁奖或放置 |
| G03 | 个人回顾界面与滚动列表 | 显示本轮称号和完整个人行为，超过 100 条仍可找到最早记录 |
| G04 | 关闭、重新打开与切换角色 | 按钮/Esc 可关；打开期间屏蔽移动/F，切人先关；计时照常 |
| G05 | 活动收尾与历史追加检查 | 庆典后加工完成、领奖、放置等仍记录；重新打开可读到新增行为 |

G01 使用 B01 的完整历史，不能直接读取只显示最近 100 条的 UI 列表。

### H：整体体验与交付

| 编号 | 这次只做什么 | 结束条件 |
|---|---|---|
| H01 | 明确的重置入口与本轮清理 | 清除角色效果、工位、蛋糕、称号、奖杯和历史，不残留旧轮状态 |
| H02 | 执行一次完整体验路径，只登记问题 | 领取→捐献→协作→偷吃→装饰→庆典→放奖杯→看回顾→关闭 |
| H03 | 修复一个已登记的阻断问题 | 一个问题一个子编号，如 H03-01；复验受影响路径，不顺手扩展 |
| H04 | UI/占位表现的专项检查 | 中文可读，提示/进度/飘字不严重遮挡；可见变化对应正确对象 |
| H05 | 生成一个 Windows 构建并验证入口 | 独立运行可进入正确场景，完成同一条体验路径 |
| H06 | 整理实际交付与操作说明 | 明确已实现/未验收项、运行入口、控制方式、原型限制 |

H03 只在确有问题时安排；H04 若发现多个独立问题，同样拆成单项修复。音效、角色动作美化和资源替换不默认加入这一轮。

## 5. 控制模块之间的影响

| 责任范围 | 可以修改的内容 | 需要跨范围时怎样处理 |
|---|---|---|
| 核心规则 | 工位、效果、外观状态、称号、奖杯、历史 | 事件或公开接口变化先列影响，不直接同时改整套 UI |
| 输入与角色 | 主控、移动、镜头、目标选择、F 转发 | 不在这里实现物品增减和称号条件 |
| 场景与表现 | 点位、模型、材质、目标锚点、工具动作 | 通过状态刷新外观，不让模型决定业务完成 |
| UI | 提示、日志窗口、飘字、进度、回顾 | 读取事件与查询结果，不再次执行业务动作 |
| 验证与记录 | 当前任务的必要检查、结果与问题清单 | 不因测试方便扩写新玩法或引入大型测试框架 |

“每次一个小任务”不代表必须独占一个文件。同一文件中已有多个职责时，先限定本次函数/范围，避免为了拆分计划再做整文件重构。

## 6. 每次派工与结束格式

主 agent 的派工内容只包含：

```text
任务编号：例如 C03
本次目标：后加入者的协作加速
前置结果：C01/C02 已通过；已有单工位和唯一参与集合
允许修改：工位推进与加入逻辑、相应的小型规则检查
必须遵守：单人10秒；先按旧人数推进，再加入新参与者
验收：1人4秒后第2人加入，再3秒完成；重复加入不加速
边界：不做打发接入、UI美化、称号和庆典
完成后：报告结果并停止，不开始 C04
```

每次结束只报告四项：完成了哪个编号、改了哪些范围、验证结果、下一项建议及阻碍。无需重新输出整份策划案，也无需为每个小项再派一个审查 agent。

任务状态统一使用：**待安排 → 进行中 → 待验收 → 已验收**；无法继续时记为“受阻”并写明条件。存在代码但未运行的任务保持待验收，不标为完成。
