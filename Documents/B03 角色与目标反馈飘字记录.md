# B03 角色与目标反馈飘字记录

日期：2026-09-19。范围：复用 `DemoHud`、`ActorView.HeadAnchor` 与 `TargetView.FeedbackAnchor`，把一次已提交的 `ActionEvent` 显示为角色头顶和交互目标处的短暂反馈。不包含工位进度、庆典、奖杯或完整回顾规则。

## 实现结论

- `DemoRuntime` 仍只通过 `Session.EventRecorded` 调用 `DemoHud.OnAction`。HUD 不重新执行交互，也不从中文日志反推状态。
- 角色飘字读取事件的 `ActorText`；共享事件按 `ParticipantIds` 为每位参与角色各创建一条，普通事件按 `ActorId` 创建一条。颜色统一复用 `ActorView.ColorForActor` 的红、黄、蓝映射。
- 目标飘字读取同一个事件的 `TargetText`，通过 `TargetId` 只做 `TargetView` 查找，再挂到 `FeedbackAnchor`。目标反馈使用中性色；内部目标 ID 不作为显示文本。
- 飘字使用非缩放时间显示 1.2 秒。事件回调、每帧更新和新飘字创建前都会清理过期或失效锚点，连续动作按同一锚点的栈位向上排列，旧对象不会继续占用栈位。

## 针对性断言

`CoreSmokeTests.FeedbackFieldsStayHumanReadableAndHudUsesTheirLifecycle` 覆盖：

- 角色与目标反馈来自已提交 `ActionEvent` 的 `ActorText` / `TargetText`；
- 核心反馈字段不包含内部 `TargetSpec.Id`；
- `DemoHud` 存在过期时间判断、对象清理和回调前清理路径；
- HUD 不把 `TargetId` 直接传入飘字文本，并保留目标 ID 过滤。

本轮以 CoreSmoke 和静态契约检查为主，未等待 Unity Play Mode；场景运行仍按《开发执行记录》中的项目锁状态单独记录。
