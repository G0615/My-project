# Unity Demo 开发计划与模块架构：四类交互版本

更新：2026-09-18  
目标：一周内约 24 小时有效投入，以 AI 辅助编码和复用资源，完成三角色、四类交互、蛋糕装饰、广场 F 庆典、全员奖杯、家园放置与查看完整个人日志的闭环。

配套：[策划案](./Unity%20Demo%20策划案.md)。本文件作为架构与规则基线；实际状态见[开发执行记录](./开发执行记录.md)。2026-09-19 起，派工节奏以[分阶段工作顺序](./Unity%20Demo%20分阶段工作顺序.md)为准：每次默认一个小任务，完成后停止，不按下文原有并行分工一次启动全部模块。

## 1. 本次需求变化及架构结论

以用户最新细化为准，覆盖旧方案：

| 项目 | 最新决定 |
|---|---|
| 角色 | 三个同时存在的角色，1/2/3 切换控制 |
| 镜头 | 固定旋转、固定缩放，切换时平滑居中新角色；默认继续跟随移动 |
| 加工 | 切果/打发各一共享批次，单人 10 秒，人数线性加速，走开/切人不中断 |
| 物资 | 不做库存、余额、数量守恒；增减仅是本次动作结果 |
| 蛋糕 | 3 个贴果切目标、3 个奶油换色目标，六等分位置；直接 F，无材料前置 |
| 偷吃/捐献 | 有效筷子决定物品堆动作，持筷不能捐献，无模式切换；不影响加工、蛋糕等交互 |
| 反馈 | 角色配色日志、角色/交互物飘字、工位上的共享进度 |
| 庆典 | 广场实体触发器，任意玩家 F；结算四称号并给三人各一奖杯，同轮只执行一次 |
| 奖杯收尾 | 家园 F 放置，再 F 查看本人完整活动日志；界面可关闭 |
| 历史 | 活动内存历史保留完整，滚动日志只截断显示，协作记录关联所有参与者 |
| 本轮后置建议 | 磁盘存档、网络同步、库存系统、中断/恢复、烤箱、拖拽编辑、昼夜天气 |

用户已确认：10 秒是单人基础时间；日志只记动作增减，世界中视为有用不完的库存。不要重新建立“允许负数的库存表”或“库存不足但放行”的系统。

底层原则保留：唯一输入、统一交互、业务与表现分离、单场景先完成。核心变化是：**工位拥有协作进度，角色拥有工具和减速状态，蛋糕拥有外观，统计拥有行为次数，反馈只展示结果。**

这比旧方案的资源交易/中断恢复更轻，但必须尽早验证三人输入、共享批次和统一日志，不能先堆满点位再接数据。

## 3. 模块边界与数据流

```text
唯一 InputRouter ── 1/2/3 ─→ ActiveActor / CameraTarget / 当前 HUD
        │
        └─ 移动 / F → 角色移动与目标检测 → InteractionAdapter
                                                   │ ActorId + TargetId + Action
                                                   ▼
                                   DemoSession：明确的业务操作入口
                                  /          |          |          \
                            工位批次     角色限时状态   蛋糕外观    行为统计
                                  \          |          |          /
                                    统一 ActionEvent（动作事件）
                                                   │
                          完整 ActionHistory 先记入，再分发表现
                                                   │
                      最近日志 / 飘字 / 模型音效 / 称号奖杯 / 个人回顾
```

一个 DemoSession 协调小型模块即可，不建通用指令总线、依赖注入、Service Locator、库存框架或行为树。模块是责任边界，不要求每个都成为独立服务。

| 模块 | 自己负责 | 不负责 |
|---|---|---|
| InputRouter / ActorSelector | 唯一输入、主控 ActorId、提示绑定；无模式切换键 | 工位计时、称号资格 |
| PlayerMotor / FixedAngleFollowCamera | 移动、读取有效速度；镜头平移、固定视角 | 资源、协作人数、角色行为计分 |
| InteractionAdapter | 稳定 TargetId、可读 Prompt、把 F 转为明确动作 | 私有库存、私有进度、拼接所有日志规则 |
| WorkStationSystem | 两类工位的批次、参与集合、共享进度、完成一次 | 键盘控制、工具期限、金币余额 |
| ActorEffectSystem | 每人筷子到期、减速层和共同到期时间；筷子有效性由时间派生 | 修改工位参与集合、冻结未控制角色时间 |
| CakeSystem | 三挂点与三表面外观、六等分位置映射、最后操作者 | 背包扣除、作者权限、拖拽编辑 |
| Participation / Celebration | 参与资格、一次性结算快照、三人颁奖；行为次数供回顾 | 从日志反推资格、比较次数、漏发无称号角色 |
| TrophySystem | 按角色的未颁发/待放置/已放置状态、摆放点与活动归属 | 通用背包、重复领奖、从 UI 直接更改状态 |
| ActivityHistory | 本轮完整有序事件、按角色/参与名单查询 | 只保留最后100条、仅按发起者过滤协作 |
| FeedbackPresenter / TrophyHistoryView | 显示日志/飘字/音效与个人回顾；打开关闭界面 | 修改业务状态、丢旧历史、按 UI 重绘再次发奖 |
| DemoBootstrap / Config | 显式引用、参数、重置和演示面板 | 自动补库存、伪造已发生的行为 |

两种工位共用一套 WorkStation 逻辑，以配置区分名称、原料/成品描述、工具表现和统计类型。不复制两套计时器代码。筷子、减速使用同一个运行时钟，但有不同的截止时间。

## 4. 最小数据模型：没有库存字段

| 数据 | 最小内容 |
|---|---|
| ActorProfile | 稳定 ActorId：1/2/3；名称、红黄蓝配色、实体引用映射 |
| ActorRuntime | 筷子到期时间、减速层数、减速到期时间；不含模式字段 |
| ActorParticipation | HasCraftParticipation、HasArtParticipation、HasEaten、HasDonated；对应四种称号 |
| ActorStats | 切果完成、打发完成、贴果切、抹奶油、偷吃、捐献次数；仅用于行为回顾 |
| WorkStationState | StationId、Cut/Whip 类型、BatchId、进度、唯一参与者集合、发起者、最近推进时刻、完成标记 |
| CakeState | FruitSlots[3] 的样式/最后操作者；CreamRegions[3] 的颜色/最后操作者；另配6个等角位置映射 |
| ActivityState | ActivityId、HasCelebrated、结算快照引用；重置前保持同一轮 |
| CelebrationSnapshot | ActivityId、结算时刻、三人参与标记/统计副本、各自称号、蛋糕外观副本 |
| TrophyState | OwnerActorId、ActivityId、HomeSlotId、Status（Unawarded / Awarded / Placed） |
| ActionHistory | 当前ActivityId完整事件列表，按Sequence有序保留，显式重置才清空 |
| ActionEvent | ActivityId、Sequence/EventId、行为、ActorId/参与名单、目标、动作增减、速度/次数变化、首次达标资格、时间 |
| Config | 10 秒工作量、基础速度 10、减速上限 10、减速期 10 秒、筷子期 60 秒默认、色板、镜头与飘字参数 |

不建立 ActorInventory、PublicInventory、CoinBalance 或总物资列表。ActionDelta 中的“金币 -10”只是此次购买动作的结果描述，不在别处找金币余额扣除。

内存状态包括工作进度、外观、限时效果、称号资格、奖杯状态和完整活动历史。ActionHistory 不按100条截断；LogView只选择最后100条显示，奖杯查询读取完整列表。物资模型一直存在，不由虚构库存量决定可见性。

奖杯的三态是本轮收尾所需的专用状态，不引入通用背包：Awarded 表示已颁发待放置，Placed 表示已摆在家中。放置后仍保留获奖事实，不能通过“手上没有奖杯”推断可以再次颁奖。

ActorId 不用 Unity InstanceID 或名字代替。角色切换只改变输入与镜头指向，不修改各人的状态和行为归属。

## 5. 输入、镜头与目标选择

### 5.1 三人输入

当前工程复制三个 PlayerController 会同时读取 WASD，不能直接复制后就算完成。

- InputRouter 只读取一次输入，再投递给当前主控的移动/交互入口。
- 按 1/2/3 清零旧角色的移动意图，切换 ActiveActorId、镜头目标、选中环与 HUD；提示由新角色的筷子有效性决定。
- 不禁用整个角色、工位或效果系统；非主控的工作与减速仍要推进。
- 切换当帧先处理选择，不把同一帧 F 传给两人。
- 不绑定任何捐献/偷吃切换键或按钮；F 执行由目标和当前角色筷子状态唯一确定的动作。
- 重复按已加入工位的 F 是“继续参与”的反馈，不开第二份同批工作。
- 个人奖杯界面打开时屏蔽当前角色移动与世界 F，不暂停工位/效果时钟；关闭按钮或 Esc 恢复，1/2/3 先关闭界面再切角色。同一输入不能连锁触发放置和查看。

### 5.2 镜头

固定相机旋转与正交尺寸/视野角。目标位置 = 当前角色的视线中心 + 固定偏移，平滑逼近；角色走动后继续跟随。

切换约 0.5 秒过渡是默认调参值，不要求精确到某一缓动曲线。快速按 1→2→3 时始终从相机当前实际位置向最新目标移动，不叠加三个镜头动画。更新位置时不每帧 LookAt 造成角度变化。

视野尺寸按广场操作区配置，家园/商店放在外侧，由同样的平移跟随覆盖。UI 固定在屏幕，世界进度条和飘字按物体坐标显示。

### 5.3 唯一 F 目标

检测用角色位置、平面朝向和距离，不能拿高位摄像机位置选择最近交互物。通过合理间距、目标优先级和当前目标稳定规则保证同一刻只高亮一个。

蛋糕总计 6 个独立 InteractionHandle，围绕中心按 60° 等间隔排列。默认位置1/3/5映射到 FruitSlots[0/1/2]，位置2/4/6映射到 CreamRegions[0/1/2]，交替布局。每个位置只有一种动作，逻辑目标和蛋糕模型 Renderer 分开；同一时刻只高亮其中一个。

水果/鸡蛋堆根据 HasActiveChopsticks(actorId, now) 提供唯一动作：有效则偷吃并禁止捐献，无效则捐献。果切/奶油无筷子时只给获得工具的说明；有筷子时可偷吃。家园、商店、筷子区、切果、打发、蛋糕、庆典触发器、奖杯放置/查看完全不受这条捐献限制影响。

提示与业务请求共用同一动作解析函数，同帧先处理工具到期再查询/执行；购买、到期和切角色立即刷新提示。捐献入口不能绕过有效筷子限制，但不把该限制做成角色全局不可交互。

家园水果领取点与三人的奖杯展示位用独立 TargetId 并保持空间间距；奖杯位按 OwnerActorId 选择本人可用目标。无奖杯时提示先举办庆典，Awarded 时提示 F 放置，Placed 时提示 F 查看。不能让一个 F 同时领水果、摆奖杯和开界面。

## 6. 工位：10 秒基准、共享进度、无中断

建议入口：

- JoinWork(actorId, stationId, now)
- AdvanceStation(stationId, now)
- CompleteBatch(stationId, batchId)

本轮不设计 CancelWork、离开释放、半步回滚、物料预留或自动续批。

### 6.1 进度计算

每批所需工作量为 10，每个唯一参与者每秒提供 1。等价公式：

```text
progress += deltaTime × participantCount / 10
完成条件：progress >= 1
```

首人 F 创建批次并加入；后来的不同角色 F 加入当前批次。首次开始/加入即把该人的 HasCraftParticipation 置为 true，立即记录大师资格；不等待批次完成。重复角色不增加人数、不清进度，也不重复授予称号。加入时先按旧人数把上一段时间推进到 now，再添加新成员，使新成员不为尚未加入时的时间加速。

两人从起点参与约 5 秒，三人约 3.33 秒；1 人做 4 秒后第 2 人加入，则再用 3 秒。成员离开范围、切换控制都不从集合删除。

### 6.2 计时属于工位，不属于人物

允许同一 ActorId 同时出现在切果、打发两个不同批次中，不建立阻止其他交互的全局 Busy 状态。这是“不考虑中断”的简化结果。

角色离开时恢复正常移动/站立动画，留在原地的工作物和工具持续表现；角色动画不能决定生产是否完成。两种进度条分别挂在水果和打发碗上，显示各自参与者颜色/人数。

### 6.3 只结算一次

达到完成时，先将该 BatchId 标为完成并结束计时，再产生事件：

- 切果：一次公共动作增减“水果 -1、果切 +1”。
- 打发：一次公共动作增减“鸡蛋 -1、奶油 +1”。
- 每位参与者的对应完成次数各 +1，供日志回顾使用；大师资格已在开始/加入时获得，完成时不再授予一次。
- 统一事件携带完整参与名单，UI 只显示一份公共产出，再分角色显示计数。
- 参与名单先复制为事件数据，再清空工位参与集合；事件不能引用随后被重用的可变列表。
- 下一次 F 创建新 BatchId；同一个完成回调或重复帧不能再次结算旧批次。
- 完成后不自动消耗时间启动下一批。

加工过程中偷吃原料也不会中断工位，因为两者都不依赖资源余量。角色在一个批次快完成时加入也获得一次完成计数，首版不追加反刷规则。

## 7. 即时行为、筷子与减速

### 7.1 即时动作结果表

| 行为 | 动作增减描述 | 实际需要修改的状态 |
|---|---|---|
| 家园领取 | 角色水果 +1 | 仅生成领取事件，不保存水果数量，不置四类称号标记 |
| 商店买蛋 | 角色金币 -1、鸡蛋 +1 | 仅生成购买事件，不置四类称号标记 |
| 捐水果/蛋 | 角色对应物品 -1、广场对应物品 +1 | 无有效筷子才提供此动作；HasDonated=true，捐献次数+1，记录慈善家资格 |
| 贴果切 | 广场果切 -1 | 替换挂点外观、最后操作者、贴装次数+1；HasArtParticipation=true |
| 抹奶油 | 广场奶油 -1 | 区域循环颜色、最后操作者、抹色次数+1；HasArtParticipation=true |
| 买筷子 | 角色金币 -10、筷子 +1 | 筷子截止时间 = now + 配置时长，相关目标提示自动更新；不改变其他交互 |
| 偷吃 | 广场被吃物品 -1、实际移速变化 | 偷吃次数、减速层与统一截止时间；HasEaten=true，记录馋鬼资格 |
| 重复加入 | 无物品变化，已在本批协作 | 不增加人数或次数，只反馈说明 |
| 举办庆典 | 三人分别[奖杯]+1，独立事件/各自配色 | HasCelebrated=true，冻结称号快照；每人TrophyState=Awarded |
| 放置奖杯 | 本人[奖杯]-1、家园[奖杯]+1 | 本人Awarded→Placed，绑定自己的固定展示位 |
| 查看奖杯 | 查看本人活动回顾，无物品增减 | 不改奖杯/结算状态；记录一次查看事件，查询本人完整历史 |

所有正常交互不检查资源、金币或装饰作者；持有效筷子不能捐献是明确的动作规则，不是资源数量检查。水果/鸡蛋堆按目标明确捐献类型，不要求系统猜“背包中哪个物品”。用户示例中的头顶增减以事件显示，不是常驻库存 UI。

### 7.2 筷子是许可状态

首版默认持续 60 秒，重复购买刷新截止时间，不维护多根筷子库存；日志“+1”表示这次获得。偷吃不消耗筷子。有效期内水果/鸡蛋堆只提供偷吃；到期收回偷吃许可，自动恢复捐献。全程不影响加工、蛋糕等其他动作，没有模式字段或切换流程。

60 秒和重复购买刷新是补充默认，应放入配置与注释，便于用户修改；10 金币采用用户给出的示例。

### 7.3 减速是带统一期限的层数

每次偷吃前先处理已到期效果，然后：

```text
slowStacks = min(10, slowStacks + 1)
slowExpiresAt = now + 10
effectiveSpeed = max(0, 10 - slowStacks)
```

当 now >= slowExpiresAt，slowStacks 一次归 0，速度回到 10。第 10 层后继续偷吃仍刷新时间并记偷吃次数，实际速度变化为 0，反馈显示“已达下限，刷新 10 秒”。

两次偷吃间隔 6 秒时，第二次把全部层数的共同截止时间改到该时刻之后 10 秒，不保留第一层原来的独立到期计时。不能用每层一个协程分别恢复 +1。

筷子和减速分别计时；非主控角色同样到期。PlayerMotor 每次移动读取 effectiveSpeed，不同时维护另一个减速后的 moveSpeed 副本。

## 8. 统一事件驱动日志与飘字

建议保留现有交互上下文/结果的适配作用，由业务入口返回明确结构：

```text
ActionEvent
  ActivityId / Sequence / EventId / ActionType / Time
  ActorId，或发起者 + ParticipantIds
  TargetId
  DisplayDeltas[]     物品/金币的本次动作增减，没有余额
  StatChanges[]      真正增加的行为次数（不做排名）
  NewlyQualifiedTitles[]  本次首次达成的称号资格，正式在庆典汇总
  GrantedTitles[]        颁奖事件所附的本次结算称号，可为空
  EffectChange       实际速度前后值、有效期变化
  MessageKind        开始 / 加入 / 已参与 / 完成 / 普通动作 / 到期
```

一次 F 的处理顺序：确定当前角色和唯一动作 → 修改必要运行状态 → 生成一次权威事件/事件组 → 写入完整ActionHistory → 分发给日志、飘字、模型和音效。庆典是一组事件：触发行为加三名接收者的颁奖事件；不能把三座奖杯全记到触发者名下。

- 不从中文日志解析库存或称号资格；资格在对应行为发生时更新。
- 不让角色飘字、物体飘字、日志各调用一次业务命令。
- UI 重绘/订阅重绑不能重放已经提交的动作。
- 资源引用缺失属于开发配置问题，给诊断并降级表现；不能用它触发重复业务或伪造产出。
- 正式点位空动作配置应在开发检查中暴露，不能默认变色冒充实现完成。

日志模板集中维护。普通动作整行按 ActorId 配色；协作行参与者名字分别着色，公共变化中性色，个人完成次数各用本人色显示。

### 完整历史与显示窗口分开

ActionHistory 保存从本轮开始到当前的全部事件。LogView只是最近100条的可见窗口，滚动、关闭和重建UI都不删除历史。无需数据库，首版一个内存 List 足够。

个人查询条件：ActivityId匹配，且 event.ActorId==ownerId **或** event.ParticipantIds包含ownerId。先按EventId去重，再按Sequence排序。一条共享完成事件可被所有参与者查询到，但全局只写一次、公共产出不复制。别人单独购买/偷吃不会出现在本人的列表。

颁奖事件的ActorId是接收奖杯的人；发起庆典另有触发者事件。即便3号此前无操作，3号也有一条自己的[奖杯]+1记录。后续放置、查看以及在制批次完成仍属于同一ActivityId，不因为称号已结算就丢记录。

TrophyHistoryView按奖杯绑定的OwnerActorId与ActivityId查询，不读随切换变化的全局ActiveActorId。打开时读取截至打开时的完整列表；关闭重开可读到新增行为。只在一次F查看入口记录一次查看事件，滚动/渲染是只读操作，不能形成“查看日志又生成日志”的循环。

FloatingText显示约1.2秒，连续事件错位/排队。三人获奖各创建对应头顶[奖杯]+1，同时写入三条同色日志；不能只给主控或镜头内角色生成事件。UI显示上限不截断历史，也不能造成某人漏发奖杯。

每次开始/加入/完成都在角色与目标上反馈；工位进度持续显示但不逐帧写日志。普通到期提示同样带角色号，切换后不会误以为当前人恢复了速度。

## 9. 庆典触发、全员奖杯、家园放置与个人回顾

### 9.1 称号资格与正式结算

四项参与标记仍按人独立判定：

| 称号 | 资格来源 | 记录时点 |
|---|---|---|
| 大师 | HasCraftParticipation | 首次开始/加入切果或打发，不等完成 |
| 艺术家 | HasArtParticipation | 首次贴果切或抹奶油生效 |
| 馋鬼 | HasEaten | 首次偷吃 |
| 慈善家 | HasDonated | 首次捐献；领取/购买不触发 |

资格false→true时记录一次达标，正式称号在广场庆典统一结算展示。次数只用于回顾，不排名。尚在加工的人也已具备大师资格；三人可得同种，一人可得四种。

### 9.2 任意角色F，一次给三人颁奖

新增CelebrationTrigger场景目标，走近显示[F]举办庆典，不再把演示面板按钮作为正常入口。任意角色可触发，持筷、无称号、远处的其他人均不构成限制。

建议入口：Celebrate(actorId, triggerId, now)。

1. 把两工位和限时效果推进到now，不强制完成或取消现有批次。
2. 检查当前ActivityId的HasCelebrated。首次调用先设置该标记，再复制称号/统计/蛋糕外观为结算快照。
3. 遍历固定角色清单1/2/3，把每人的奖杯状态从Unawarded设为Awarded，绑定同一ActivityId和各自HomeSlotId。不给“必须有称号/先参与”的额外门槛。
4. 创建触发者的庆典事件，以及三个不同接收者的TrophyAwarded事件；每人的DisplayDeltas包含本人[奖杯]+1，GrantedTitles可以为空。
5. 所有状态与历史记录先完成，再播放三人的飘字、同色日志和约8秒庆祝表现。某个View引用缺失不能阻断其他人获奖。

同轮重复F改为查看已结算结果，不重算、不重播发奖、不增加第二座奖杯。进入新一轮必须显式重置，取消旧版“结束后可重新举办”的默认规则。

称号快照在触发时固定；工位/效果照常继续。后续完成和收尾行为继续记入同一轮历史，奖杯查看可读到它们。正常演示从此进入回家放置/查看收尾，不自动开始下一轮。

### 9.3 每人一个奖杯位置

默认同一家园区域划三个固定底座，按红黄蓝与名字标明所属者。它们和苹果领取点分开，不新增房屋或自由放置系统。

建议入口：PlaceTrophy(actorId, homeSlotId)。

- 必须匹配本人底座和当前ActivityId的Awarded状态；未颁发时只给参加庆典的引导，Placed时F已经变为查看，不提供重复放置。
- 先把Status设为Placed，再让View根据状态显示一个奖杯实例。
- 记录本人[奖杯]-1、家园[奖杯]+1，在本人和底座上显示反馈。这是一次放置结果，不是通用背包数量。
- Placed仍表示已经获奖，不能用于再次领取；View刷新时不得额外克隆一座。
- 持筷与减速不影响放置/查看规则，只影响走到点位所需时间。

### 9.4 查看的是自己的完整历史

建议入口：OpenTrophyHistory(actorId, trophyId)。奖杯绑定OwnerActorId/ActivityId，仅给对应主控提供查看提示；其他人的奖杯显示所有者，不冒用当前角色记录。

打开前记录一次InspectTrophy事件，再调用只读GetActorHistory(activityId, ownerId)。界面标题明确写“X号玩家·本次活动回顾”，上方显示结算称号，列表按时间展示本人完整行为，支持滚动。

包含领取、购买、捐献、加工开始/加入/完成、偷吃、装饰、资格、奖杯颁发、放置、查看等相关事件；共享批次按参与名单归属。日志没有最多100条的回顾截断。

关闭按钮或Esc关闭；1/2/3先关闭再切人。界面打开时阻止移动和世界F穿透，但不暂停工位/效果；关闭恢复正常输入。重复打开不领奖、不重新放置、不改写历史。若展示期间有新事件，关闭再开即可看到。

### 9.5 本轮完成边界

流程为：广场F举办 → 三人各得奖杯 → 回家F放置 → 对本人奖杯F查看完整列表 → 关闭界面，演示结束。

保留本轮状态、奖杯和完整历史直到显式重置，方便三人分别查看；重置要同时清奖杯模型/状态、历史和结算标记，不能残留上一轮数据。首版仍不承诺退出后持久化，无需为了奖杯增加磁盘存档系统。

值得做的少量逻辑测试：工作人数积分和成员去重；批次只完成一次；减速刷新/下限/全清；参与称号与一次性全员发奖、奖杯状态迁移、超过100条的个人/协作历史查询。输入手感、目标选择、镜头、进度位置、中文和飘字需实机验证，不写大量复刻 UI 实现的测试。

至少让一位未读文档的人尝试：能否看懂此刻 F 是捐献还是偷吃，加入后是否注意到加速，能否认出另一个角色做了什么。记录一个真实问题和一次改动后的结果，作为 JD 中迭代能力的证据。

## 13. 扩展时改哪里，避免互相牵连

| 调整 | 主要改动 | 不应连带重写 |
|---|---|---|
| 10秒改8秒、协作效率改变 | WorkConfig/共享推进公式 | 镜头、日志模板、筷子 |
| 更换角色/工位模型 | Prefab/表现映射 | 行为统计、工位进度 |
| 筷子时长改动 | EffectConfig | 减速的独立10秒规则 |
| 偷吃减速规则改动 | ActorEffectSystem与反馈事件 | 物品点位、蛋糕状态 |
| 改称号获得条件 | Participation更新与资格查询 | 工位进度、输入、日志模板 |
| 改奖杯样式/摆放点 | 奖杯View与HomeSlot映射 | 发奖次数、历史与称号规则 |
| 改日志显示条数 | LogView显示窗口 | 完整ActionHistory、奖杯个人查询 |
| 增加蛋糕区域或换造型 | 配置/目标映射/View | 加工和偷吃规则 |
| 加存档 | 对实际状态做快照/恢复，并另定在制批次语义 | 不从日志重演动作 |
| 恢复真实经济 | 新增资源系统并重新设计失败/消耗规则 | 当前无库存原型不能直接冒充已支持 |
| 真实联网 | 重新设计权威状态、并发、时钟同步 | 不宣称换输入来源即可上线 |

此次结构为明确边界服务，不承诺未来需求零成本接入。

## 14. 本版交付完成定义

- 独立构建可进入实际场景，三角色与镜头行为符合要求。
- 四类交互全部可用，资源不足不会成为前置失败。
- 切果/打发共享进度、人数加速、离开不中断、批次一次完成。
- 蛋糕六等分位置上3个果切挂点、3个奶油区域均能直接F操作，总计6点。
- 持有效筷子不能捐献，无模式切换；切果、打发、蛋糕等不受影响，期限及减速10秒刷新真实生效。
- 每次行为有角色颜色日志与角色/目标飘字，不显示库存总量。
- 四类行为形成大师/艺术家/馋鬼/慈善家资格，无排名；任意玩家可在广场实体触发器按F结算。
- 三人各获一座奖杯，无称号者也有；各自头顶与同色日志均显示[奖杯]+1，重复F不再发。
- 回家F放置本人奖杯，再F打开可关闭的个人完整行为列表，包含全部协作与收尾记录，超过100条不丢失。
- 苹果领取与奖杯目标明确分离，奖杯属于本人，界面不串角色、不穿透世界输入。
- 有一条完整演示、一份实际验收结果和至少一条试玩迭代记录。
- 说明本地多角色模拟、AI辅助范围与资源来源，区分已实现与后续设想。

旧《底层交互架构开发任务说明》仍可帮助理解基础接口，但其中旧阶段限制不作为本版交付标准。
